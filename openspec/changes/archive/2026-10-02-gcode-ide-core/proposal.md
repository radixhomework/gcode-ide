# Proposal: gcode-ide-core

## Why

G-code for the GRBL-driven PROVER 3018 has to be trustworthy before it reaches the machine: out-of-bed moves, wrong units, or excessive feeds waste material at best. Machine control already exists in the sibling project `grbl-machine-controller` (jogging, streaming, probing), but nothing on the desk produces or verifies the code it runs. This change starts `gcode-ide` as a small desktop IDE whose central artifact is the G-code document — written by hand today, generated by import wizards in later phases — with a live preview that makes the toolpath visible before it is cut.

## What Changes

This is the first phase of a greenfield application; nothing exists yet but a README.

- Create the application skeleton: Python + PySide6 desktop app (`app/` package, `pyproject.toml`, pytest, ruff, PyInstaller-ready), mirroring the conventions of `grbl-machine-controller` so both projects share one idiom.
- Document-centric main window: create, open, save, and save-as G-code documents (`.nc` / `.gcode`), with unsaved-change tracking.
- G-code editor with syntax coloring for the GRBL dialect (motion words, parameters, comments), line numbers, and current-line indication.
- A GRBL-dialect G-code parser that produces a toolpath model with per-line attribution — the shared engine for preview, statistics, and (in later phases) generator round-trip tests.
- 2D top-down toolpath preview: bed outline, rapid vs. cut moves, depth shading, bidirectional line↔segment sync, and live re-parse while editing.
- Status-bar diagnostics: toolpath bounding box, estimated run time, and out-of-bed / feed-cap warnings derived from the active machine profile.
- Machine profiles as plain YAML data, shipping with a "PROVER 3018" preset (300×180×45 mm bed, feed caps), designed as an interchange format readable by `grbl-machine-controller`.

**Explicit non-goals for this change:** driving the machine (serial/USB — owned by `grbl-machine-controller`); SVG import and any G-code generation (Phase 2); tool library and tool-aware generation (Phase 3); 3D preview; multi-document tabs.

## Capabilities

### New Capabilities

- `gcode-editor`: Document lifecycle (new/open/save) and the editing experience — syntax coloring for GRBL G-code, line numbers, unsaved-change tracking.
- `gcode-parsing`: Interpreting GRBL-dialect G-code text into a toolpath model with line attribution, tolerant of comments and unsupported-but-harmless words, with explicit diagnostics for what cannot be interpreted.
- `toolpath-preview`: 2D top-down visualization of the parsed toolpath against the machine bed, with bidirectional editor↔preview selection sync and live updates, plus toolpath statistics and safety warnings.
- `machine-profiles`: Machine definitions (bed size, feed limits, safe-Z default) as YAML data files with a built-in PROVER 3018 preset and user-selectable active profile.

(none — no specs exist yet)

## Impact

- **Code**: entire `gcode-ide` repo is new; `app/` package layout, entry point `app.main:main`, tests under `tests/`.
- **Dependencies**: Python ≥3.9, PySide6 (UI), PyYAML (profiles/config). No SQLite yet — deferred to the tool-library phase.
- **Ecosystem**: handoff to `grbl-machine-controller` is a `.nc` file on disk; the machine-profile YAML format is designed so both projects can read it without sharing code.
- **Later phases build on this**: the parser becomes the round-trip test rig for the SVG-import generator (Phase 2) and consumers of profiles/tools (Phase 3+).
